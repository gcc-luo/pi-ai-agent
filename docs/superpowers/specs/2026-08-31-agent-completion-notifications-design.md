# Agent 任务完成通知与未读角标设计

## 背景

PI AI Agent 允许多个会话独立运行任务。用户在任务运行期间可能最小化桌面端、
切换到其他应用，或继续查看另一个会话。当前任务完成后缺少主动提醒，用户也无法
从会话列表判断哪些后台会话出现了需要关注的新结果。

本设计建立一条完整闭环：Agent 任务结算后持久化未读状态，根据用户是否正在查看
对应会话决定是否发送系统通知，并在用户点击通知后恢复窗口、打开目标会话、定位
结果消息并清除未读。

## 目标

- Agent 任务成功或失败后产生一个稳定、可幂等处理的结算事件。
- 用户未在前台查看对应会话时发送操作系统原生通知。
- 会话未读状态持久化，应用重启后仍然保留。
- 会话列表展示独立未读数，应用图标展示总未读数。
- 点击系统通知后准确恢复到产生结果的项目、会话和消息。
- 当前在前台查看目标会话时不弹通知，也不留下未读。

## 本期范围

本期支持：

- `completed` 与 `failed` 两类任务结算。
- 原生系统通知。
- 会话未读角标与应用总角标。
- 点击通知恢复窗口、跨项目跳转、消息定位和已读清除。
- 通知与未读的数据库持久化、重放幂等和重启恢复。

本期不支持：

- 通知内直接回复。
- 多条通知的定时聚合。
- `waiting_user`、`permission_required` 等扩展通知类型。
- 跨设备或多客户端的已读同步。

数据结构和接口预留通用通知类型，后续扩展不需要重做核心模型。

## 方案选择

采用“服务端持久化未读，Web 端编排 Tauri 通知”的方案。

服务端掌握 Agent 生命周期、消息持久化和 SQLite 数据库，适合生成稳定任务标识、
创建通知记录并维护未读真相。Web 端掌握当前导航状态并可直接查询 Tauri 窗口状态，
适合判断用户是否正在查看目标会话、展示通知和执行点击跳转。

不将全部逻辑放进 Tauri/Rust 主进程，因为 Agent 事件来自 Node sidecar，新增跨进程
事件桥会扩大改动面。不采用纯前端本地状态，因为它无法可靠满足重启持久化和事件
重放幂等要求。

## 架构与职责

### Agent 结算

每次服务端接受新的普通用户提示时，为该次运行生成稳定 `taskId`，并在该 Session
的运行状态中保存：

- `taskId`
- 运行开始时间
- 最后一个成功持久化的 assistant 消息 ID 与正文
- 当前运行最后一个终止错误

`agent_settled` 是正常运行的权威结算边界。服务端不得把单个 `message_end` 当作任务
完成，因为一次运行可能包含多个模型轮次和工具调用。同步拒绝、进程退出等不会收到
`agent_settled` 的失败路径，也必须通过同一个结算函数收口。

结算函数只允许同一个 `taskId` 成功写入一次。它创建通知记录、更新会话未读数并发出
`agent_task_settled`。手动上下文压缩不是用户任务，不产生通知或未读。

### 服务端持久化

为 `sessions` 增加：

- `unread_count INTEGER NOT NULL DEFAULT 0`
- `last_read_message_id TEXT`

新增 `notifications` 表：

- `id TEXT PRIMARY KEY`
- `task_id TEXT NOT NULL UNIQUE`
- `project_id TEXT NOT NULL`
- `session_id TEXT NOT NULL`
- `message_id TEXT`
- `type TEXT NOT NULL`
- `title TEXT NOT NULL`
- `body TEXT NOT NULL`
- `is_read INTEGER NOT NULL DEFAULT 0`
- `created_at INTEGER NOT NULL`
- `read_at INTEGER`

本期 `type` 取值为 `task_completed` 或 `task_failed`。通知记录通过唯一 `task_id`
防止 WebSocket 重放或重复结算造成重复累计。

通知写入和 `sessions.unread_count + 1` 必须位于同一数据库事务。标记会话已读时，
在同一事务内把该会话的所有未读通知设为已读、更新 `last_read_message_id`，并把
`unread_count` 清零。

`SessionDto` 增加 `unreadCount` 与 `lastReadMessageId`。会话列表接口因此可以在应用
启动时直接恢复角标。

新增接口：

- `POST /api/sessions/:id/read`
  - 请求体可带 `messageId`。
  - 幂等清除该会话未读，并返回更新后的 `SessionDto`。
- `GET /api/notifications/unread-count`
  - 返回所有未删除会话的未读总数。
  - 应用启动、任务结算和标记已读后用于校准应用总角标。

### 结算事件

服务端向订阅者发送：

```ts
type AgentTaskSettledEvent = {
  type: "agent_task_settled";
  notificationId: string;
  taskId: string;
  projectId: string;
  sessionId: string;
  messageId?: string;
  title: string;
  summary: string;
  status: "completed" | "failed";
  completedAt: number;
  unreadCount: number;
};
```

成功任务使用最终 assistant 消息作为 `messageId` 和摘要来源。失败任务优先使用最终
错误；没有可定位消息时省略 `messageId`。标题使用会话标题，未命名会话使用现有
“新会话”文案。

摘要只包含纯文本：规范连续空白，移除不适合通知展示的结构化内容，并截断到约
200 个字符。完整回复仍只在聊天界面展示。

## 用户是否正在查看会话

Web 端在收到结算事件后读取：

- 当前是否运行在 Tauri。
- Tauri 窗口是否可见、聚焦、未最小化。
- 当前导航是否为聊天页。
- 当前项目和会话是否与事件目标一致。

只有上述条件全部成立，才视为用户正在查看目标会话。此时立即调用已读接口，不弹
系统通知。其他情况保留服务端创建的未读状态，并在 Tauri 环境发送原生通知。

浏览器开发环境没有原生通知和应用图标角标，但仍处理未读状态与会话列表角标。

进入会话或窗口重新获得焦点时，如果该会话存在未读，也调用已读接口。仅仅因为
后台窗口中保存着目标会话选中状态，不能自动清除未读。

## 原生通知

通知内容：

- 应用名：`PI AI Agent`
- 标题：会话标题
- 正文：成功回复摘要或失败错误摘要
- 数据：`notificationId`、`projectId`、`sessionId`、可选 `messageId`

桌面 Store 在初始化时注册一次 Tauri notification `onAction` 监听器。通知点击后：

1. 恢复已最小化窗口。
2. 显示隐藏窗口。
3. 聚焦窗口。
4. 把通知携带的导航目标交给应用根组件。
5. 切换到聊天页和目标项目。
6. 等待项目会话列表完成加载，再选择目标会话。
7. 等待消息渲染，定位 `messageId`；无消息 ID 时滚动到底部。
8. 调用已读接口并更新所有角标。

跨项目跳转不得依赖固定延时。根组件应显式等待项目 watcher 或复用一个可等待的导航
函数，避免自动选择第一个会话覆盖通知目标。

通知关闭或忽略不改变数据库未读状态。通知权限被拒绝或系统通知调用失败也不能影响
任务结算；侧栏角标是始终可用的兜底入口。

## 会话与应用角标

侧栏在非当前会话右侧显示未读数：

- 1 到 99 显示实际数字。
- 大于 99 显示 `99+`。
- 当前会话不显示角标。

应用总未读为所有未删除会话未读数之和。Web 端通过
`GET /api/notifications/unread-count` 获取跨项目总数，不能只累加当前项目会话。

平台表现：

- macOS 使用 Tauri `setBadgeCount`。
- Windows 根据数量生成小尺寸透明 PNG 数字图标，通过 `setOverlayIcon` 设置任务栏
  overlay；总数为零时清除。
- 不支持原生数字角标的平台允许静默降级，不影响侧栏未读。

角标更新失败只记录诊断信息，不阻断主要流程。

## 错误处理与一致性

- 通知写入和未读累计使用事务，避免二者部分成功。
- `task_id` 唯一约束和仓储层幂等逻辑共同防止重复累计。
- 已读接口幂等，多次打开同一会话不会产生负数或错误。
- 会话已被删除时，迟到的结算事件不创建孤立通知。
- 通知点击时项目或会话已删除，则恢复应用并停留在可用页面，不抛出未处理异常。
- Tauri API、通知权限和角标能力不可用时，Web 功能继续正常运行。
- 失败任务没有最终 assistant 消息时，打开目标会话并滚动到底部。

## 测试策略

### 服务端

- 迁移为现有会话填充零未读，并创建通知表和唯一约束。
- 成功结算写入通知、增加未读并返回最终消息 ID。
- 失败结算记录错误摘要，允许没有消息 ID。
- 同一 `taskId` 重复结算不重复写入或累计。
- 标记已读在事务中更新通知、会话未读和最后已读消息。
- 总未读查询包含所有项目。
- 手动压缩、取消和非任务状态不产生完成通知。

### Web

- 仅在窗口可见、聚焦、未最小化、处于聊天页且目标会话相同时自动已读。
- 其他会话、其他导航页、失焦、隐藏和最小化时保留未读并通知。
- 非 Tauri 环境不调用桌面 API。
- 摘要与角标都正确处理 `99+` 边界。
- 选择会话和窗口重新聚焦时清除未读。
- 点击通知可跨项目导航、精确滚动或在失败时滚到底部。
- 通知权限拒绝和桌面 API 失败不破坏未读状态。

### 验收场景

1. Session A 在前台完成：正常显示回复，不弹通知，不保留未读。
2. 从 Session A 切到 B 后 A 完成：弹通知，A 未读为 1，总角标加 1。
3. A 运行时最小化：完成后弹系统通知并保留未读。
4. 点击通知：恢复窗口，打开 A，定位最终回复并清除 A 未读。
5. A、B、C 分别完成：各自独立未读，总角标为三者之和。
6. 关闭通知但不打开应用：未读保持不变。
7. 重启应用：数据库中的未读数量继续显示。
