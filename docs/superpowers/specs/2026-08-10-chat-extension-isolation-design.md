# 聊天进程扩展隔离设计

## 背景

Windows 安装版启动聊天时，Pi 会自动发现
`~/.pi/agent/extensions` 下的用户全局扩展。任意扩展缺少运行依赖，
都会使 Agent 在调用模型前退出。例如 `pi-web-access` 缺少
`@mozilla/readability` 时，普通对话也会直接报错。

Web UI 已通过 `--extension` 显式注入自定义模型扩展和当前会话选中的
浏览器、电脑扩展，因此聊天进程不需要隐式加载用户全局扩展。

## 方案

为 Web UI 的默认 RPC 启动参数增加 `--no-extensions`：

- 禁止 Pi 自动发现用户和项目扩展。
- 保留 `--extension` 显式传入的自定义模型及会话插件扩展。
- 仅调整默认参数；显式设置 `PI_ARGS` 的部署仍完全尊重管理员配置。
- 不改变 Coding 终端的默认行为，避免影响用户在原生 Pi TUI 中使用扩展。

## 错误处理

用户目录中的损坏扩展不再影响 Web UI 普通聊天。显式选中的内部扩展
若加载失败，仍按现有机制显示错误，以便暴露应用自身的打包问题。

## 测试

新增配置层回归测试，验证：

1. 嵌入式安装版的默认 RPC 参数包含 `--no-extensions`。
2. 开发环境通过 `npx` 启动时同样包含该参数。
3. 显式 `PI_ARGS` 不会被应用静默改写。
4. Coding TUI 参数不继承 RPC 专用的扩展隔离参数。
