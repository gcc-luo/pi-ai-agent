# Windows PortableGit 发布恢复设计

## 背景与根因

v1.3.6 在 Windows 自动更新后无法启动后端，启动页显示 Windows
`os error 193`。现场安装目录中的 `portable-git.exe` 和
`portable-git.sha256` 均为 0 字节，而 `pi-node.exe` 是有效的 PE 文件并可独立
运行。因此，失败点不是 Node sidecar，而是 sidecar 启动前执行空的
PortableGit 自解压程序。

根因是发布工作流直接执行 `pnpm prepare-sidecar && npx tauri build`，绕过了桌面
包 `build` 脚本中的 `prepare-shell-runtime`。Rust `build.rs` 为测试构建创建的空
占位文件随后被 Tauri 当作正式资源打入安装包。

此外，v1.3.6 标签对应的桌面包和 Tauri 配置仍声明版本 1.3.5，导致发布标签、
更新清单和安装包内部版本不一致。

## 目标

1. 所有正式 Windows 构建在打包前都准备经过 SHA-256 校验的 PortableGit。
2. 空文件、缺失文件或校验不匹配时，构建必须失败，不能生成正式安装包。
3. 运行时资源损坏时，后端继续启动，不因可选 Shell 运行环境使整个应用不可用。
4. 发布标签、桌面包版本和 Tauri 版本必须一致。
5. 修正版安装包能够覆盖 v1.3.6 安装目录中的 0 字节资源并恢复功能。

## 非目标

- 不在应用启动期间联网下载 PortableGit。
- 不改变服务端 API 或用户数据格式。
- 不自动修改用户配置中的 `shellPath`。
- 不在本次修复中重构整个发布工作流。

## 方案

### 构建入口

发布工作流调用桌面包的标准构建脚本，不再自行拼接部分准备命令。标准构建脚本
依次执行 Shell 运行环境准备、sidecar 准备和 Tauri 构建，确保本地构建与 CI
使用同一条路径。

在进入 Tauri 构建前执行独立的资源校验：

- `portable-git.exe` 必须存在且大小大于 0；
- 校验文件必须存在且包含预期的 SHA-256；
- 可执行文件的实际 SHA-256 必须与校验文件和固定值一致。

Rust `build.rs` 只允许为测试或非分发构建创建占位文件。正式 Windows 打包必须
显式设置由标准构建脚本传入的环境标记；在该模式下，资源无效时立即失败。

### 运行时降级

PortableGit 是命令 Shell 的增强运行环境，不是 HTTP 后端启动的必要条件。
启动时先验证归档和校验文件：

- 有效时，沿用现有缓存提取流程，并将内置 `bin` 放到 sidecar 的 `PATH` 前端；
- 无效、缺失或提取失败时，记录包含路径和原因的错误日志，使用原始 `PATH`
  启动 sidecar；
- 不把该降级错误传递为 sidecar 启动失败。

这样用户仍能打开应用和使用更新功能。若系统没有可用 Bash，只有实际调用 Shell
的任务会给出相应错误，而不会阻断整个后端。

### 版本一致性

新增发布校验脚本，读取发布标签、`apps/desktop/package.json` 和
`apps/desktop/src-tauri/tauri.conf.json`：

- 三者版本必须完全相同；
- 标签必须符合 `v<major>.<minor>.<patch>`；
- 不一致时在构建任务开始阶段失败。

修复提交将桌面包和 Tauri 版本统一提升到下一修复版本，避免覆盖已发布的
v1.3.6 资产。

## 数据流

1. 发布标签触发 CI。
2. 版本校验脚本验证标签和两个配置版本。
3. 标准桌面构建准备并验证 PortableGit 与 Node sidecar。
4. Tauri 打包经过验证的资源。
5. 用户安装修正版，NSIS 覆盖旧安装目录中的 0 字节文件。
6. 应用启动并验证 PortableGit；有效则提取，无效则降级启动后端。

## 错误处理与日志

- 构建期错误必须包含缺失路径、预期摘要和实际摘要。
- 运行时降级使用错误级日志记录，但不展示“后端服务无法启动”页面。
- Node sidecar 自身启动失败仍保留现有启动错误页面。
- 缓存标记有效但 `bash.exe` 缺失时，重新提取；重新提取失败则降级。

## 测试

### Node 测试

- 发布工作流使用标准桌面构建入口。
- 空 PortableGit 文件无法通过资源校验。
- SHA-256 不匹配无法通过资源校验。
- 有效资源可以通过校验。
- 标签与两个配置版本不一致时发布校验失败。
- 三个版本一致时发布校验通过。

### Rust 测试

- 有效的内置 Shell 路径被加入 sidecar `PATH`。
- Shell 资源准备失败时返回降级结果，而不是中止 sidecar 启动。
- 无内置 Shell 时保留原始 `PATH`。

### 验证

- 先运行新增定向测试，验证红灯后再实现。
- 运行桌面 Node 测试、Rust 测试、Web 类型检查和服务端相关测试。
- 执行 Windows 调试构建，检查打包目录中的 PortableGit 文件非空且摘要正确。
- 检查生成安装包版本与发布版本一致。

## 恢复与发布说明

已安装 v1.3.6 的程序本身无法通过远程方式修改。发布修正版后，用户需要通过
应用更新入口或手动运行修正版安装包完成一次覆盖安装。覆盖安装不会删除用户数据，
并会用有效资源替换安装目录中的 0 字节文件。运行时降级逻辑可防止后续类似资源
损坏再次让整个应用不可启动。
