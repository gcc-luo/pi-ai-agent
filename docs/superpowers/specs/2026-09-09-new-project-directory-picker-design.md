# 新建项目目录选择交互设计

## 背景

当前 `NewProjectDialog` 使用自定义目录浏览器逐级浏览目录，同时要求用户手动填写项目名称。这个流程步骤较多，而且项目名称通常与工作目录最后一级目录名相同。

本次调整统一以“选择工作目录”为核心：用户选定目录后立即创建项目，项目名称自动取目录最后一级名称。

## 目标与范围

- 桌面端点击“新建项目”后直接打开操作系统目录选择器。
- 浏览器端保留服务端目录浏览能力，但移除项目名称输入和手动路径跳转，简化为目录浏览与“选择当前目录”。
- 两端都关联用户选择的原始目录，不复制或上传目录内容。
- 保留取消操作；用户取消系统选择器或关闭浏览器弹窗时不创建项目。
- 复用现有的新建项目入口，包括项目管理弹窗和首次使用欢迎页。
- 不改变后端 `POST /api/projects` 的请求结构与校验规则。

## 交互设计

### 桌面端（Tauri）

1. 用户点击“新建项目”。
2. 调用 Tauri dialog 插件的目录选择能力，单选目录。
3. 用户取消时直接结束流程，不显示错误。
4. 用户选择目录后，从路径中提取最后一级目录名作为项目名称。
5. 立即调用现有创建项目回调并关闭新建项目流程。
6. 创建失败时保留现有错误处理方式，不伪造成功状态。

### 浏览器端

1. 用户点击“新建项目”后打开精简目录浏览弹窗。
2. 默认从服务端用户主目录开始浏览。
3. 双击目录进入下一级目录；单击目录只改变选中项，避免无法进入子目录。
4. 使用“选择当前目录”按钮创建当前选中目录；没有选中项时选择当前路径。
5. 项目名称始终从最终 `workdir` 的最后一级目录名推导，不展示可编辑名称输入框。
6. 保留返回上级、加载中、空目录和路径错误状态。

## 技术方案

### 前端组件

- 在 `NewProjectDialog.vue` 中按 `isTauri()` 分支处理桌面端与浏览器端。
- 桌面端动态导入 `@tauri-apps/plugin-dialog`，调用 `open({ directory: true, multiple: false })`。
- 新增一个跨平台路径末级名称提取函数，兼容 Windows `\\` 和 POSIX `/` 分隔符，并去掉路径末尾分隔符。
- 浏览器端复用现有 `api.browseDir`，删除手动路径输入和项目名称输入。
- 浏览器端增加“选择当前目录”操作，并在创建期间禁用重复点击。
- 保持 `@create(name, workdir)` 事件接口，避免改动项目管理弹窗、欢迎页和后端调用链。

### 后端与数据流

浏览器端仍通过 `GET /api/fs/browse` 获取真实目录列表，因此服务端可以获得绝对路径；桌面端由 Tauri 返回绝对路径。两端最终都调用现有的 `POST /api/projects`：

```text
选择目录
  → 推导 name = workdir 最后一级目录
  → emit("create", name, workdir)
  → api.createProject(name, workdir)
  → 刷新项目列表
```

后端无需新增 API、字段或数据库迁移。

## 错误处理

- Tauri dialog 导入或调用失败：关闭流程并显示现有统一错误提示；不发送创建请求。
- 用户取消目录选择：静默结束，不创建项目。
- 浏览器目录读取失败：保留弹窗，显示现有加载失败状态，允许关闭或重试。
- 目录名称为空（例如根目录）：使用现有的 `Untitled` 兜底名称，避免违反后端的名称必填校验。
- 创建请求进行中：按钮禁用，避免重复创建；请求失败后恢复可操作状态。
- 保持后端对目录存在性和目录类型的最终校验。

## 验证方案

- 为路径末级名称提取函数添加 Windows、POSIX、尾部分隔符和根目录测试。
- 更新 `NewProjectDialog` 组件测试，验证桌面端调用目录选择器、取消不创建、选中目录自动生成名称。
- 更新浏览器端组件测试，验证双击进入、选择当前目录、自动生成目录名和创建按钮状态。
- 运行 Web 类型检查与相关单元测试。
- 手动验证桌面端和浏览器端各一条完整创建流程，并确认项目列表刷新。

## 非目标

- 不实现目录内容上传或复制。
- 不改变项目重命名、删除和文件浏览功能。
- 不修改后端项目模型、数据库结构或创建接口。
