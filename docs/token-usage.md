# Token 用量与上下文优化

每轮回复的“已工作”耗时后显示该轮输入、输出、已报告用量的模型调用次数，以及读取文件、搜索代码、执行操作等分类次数。正在执行时也显示已报告用量和操作次数；没有 usage 的历史不伪造 Token 数字。纯文字回复有 usage 时同样展示用量。

输入区上方始终显示会话累计输入、输出，发送新问题不会清零。点击数字仍可查看本次与会话累计、缓存读写、工具调用数和最新一轮逐次调用明细，并保留压缩入口。输入使用蓝色、输出使用橙色，明暗及灰色主题均适配；箭头和提示文字同时标识方向。

## 统计口径

- 本次：对应用户消息之后、下一条用户消息之前的助手消息之和；工具循环产生的多轮模型调用属于同一次请求。每轮标题独立统计，底部明细中的“本次”指最新一轮。
- 会话累计：当前历史和实时消息去重后的用量总和，不是模型上下文窗口占用。
- 输入（含缓存）：Pi 的 `usage.input + usage.cacheRead + usage.cacheWrite`。例如未缓存输入 2K、缓存读取 8K，总输入显示 10K。
- 最近已报告调用：最后一条含 usage 的模型响应；不将它标为精确的当前上下文占用。
- 缓存缺失显示 `—`。模型适配器可能将不支持的缓存统计归一化为 0，因此 0 不保证确实没有缓存。
- 只有响应报告的 usage 可以统计；未报告的失败重试、压缩调用不计入。此面板不是计费账单。

历史数据库 ID 和实时事件 ID 不同，因此复用聊天消息合并逻辑，按助手时间戳识别同一模型响应。统计不再通过 `message_end` 事件递增，避免重放重复计数、历史异步加载覆盖实时增量。重放缺少 `message_start` 时也保留最终消息及用量。

## 上下文优化

1. 文件交付协议移到 `context-policy` 扩展的稳定系统提示中。保留原有 artifact 功能，不再在每条用户消息后追加相同说明；现有历史里的旧说明不会被破坏性删除。
2. 仅当项目可见范围内存在已启用的连接器时加载连接器工具和会话凭据。连接器状态变化后，下次空闲发送会重建进程并继续原会话，不中断当前任务。
3. 用量面板提供“压缩上下文”。运行中禁用，服务端也拒绝并发压缩。压缩成功、失败和写入失败均恢复可用状态，不额外保存用户消息。

压缩会生成摘要，有额外模型消耗且可能遗漏细节，不会清零累计用量。切换话题建议新建会话。自动压缩仍沿用现有配置。

本次不强行限制工具轮数，不自动改写项目的 AGENTS.md，不根据关键词关闭工具，不覆盖模型提供商缓存策略。Pi 已有工具输出截断；进一步缩短读取结果或改变任务策略，应使用同一模型、同一任务的调用明细评估质量和成本后再调整。
